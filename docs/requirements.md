# 要件定義書：クエスト質問チャット

- 作成日：2026-11-15
- 状態：下書き（「仮」と書いた数字と、10章の未決事項は確認待ち）
- 関連：[設計書](design.md)／[判断の記録](decisions.md)

## 1. 背景

AI自動運転クエスト（https://quest-app.example.com/）は、AI自動運転合宿の復習用Webアプリである。講義ごとの4択問題、講義ノート（要約動画・要点・課題）、用語ノートを持つ。

受講生は、問題の解説や課題の手順を読んでも分からないとき、今は次のどちらかをしている。

- Claude などのAIに自分で聞く。
- Discord やサポート枠で人に聞く。

前者は「自分がいま何をしていて、何が分からないか」を自分の言葉で説明する必要があり、PC操作や用語に慣れていない人ほどここでつまずく。後者は返事を待つ時間がかかる。

## 2. 目的

クエストで行き詰まった受講生が、**アプリを離れずに、状況を説明し直すことなく、講義の内容に沿った答えをすぐ得られる**ようにする。

合わせて、受講生がどこでつまずいているかを運営が把握し、次の問題・講義ノートの改善に使えるようにする。

## 3. 想定する利用者

### 3.1 主な利用者（ペルソナ）

| 項目 | 内容 |
|---|---|
| 立場 | 30代の経営者。AI事業を始めたい |
| PCの習熟度 | 操作は苦手。Claude Code をやっとダウンロードできた段階 |
| 知らない言葉 | ターミナル、パス、API、リポジトリなどはまだ自分の言葉で説明できない |
| 困る場面 | 課題の手順どおりにやったつもりが動かない／解説の用語が分からない／エラーが出たが何を意味するか分からない |
| 使える時間 | 本業の合間。調べ物に長い時間はかけられない |
| 求めるもの | 「次に何を押せばいいか」が分かる短い答え |

### 3.2 その他の関係者

| 関係者 | 関わり方 |
|---|---|
| 運営（講義を作る人） | 溜まった質問を見て、問題・講義ノート・用語を足す |
| 開発者（本人） | チャットの仕組みを作り、料金と品質を管理する |

## 4. 「Claude に直接聞くより速い」を何で実現するか

この仕組みの価値は、Claude より賢いことではない。**聞くまでの手間と、答えの読みやすさ**で勝つ。

| Claude に直接聞くときの手間 | このチャットでの解消方法 |
|---|---|
| 別のアプリを開いて切り替える | クエストの画面内にチャットがある |
| 「いま第何回の何をやっていて」を説明する | アプリが、開いている回・画面・問題を自動で添える |
| 何と聞けばいいか分からない | その画面でよくある質問をボタンで出す |
| 一般論が返ってきて、講義のやり方と違う | 講義資料だけをもとに答え、第何回の資料かを示す |
| 答えが長く、どこから読めばいいか分からない | 結論を先に1〜2文、次に操作を番号付きで示す |
| 知らない用語が答えに混ざる | 用語を使うときは、用語ノートの説明を1行添える |

### 4.1 答えにたどり着く順番

AIに聞くのは最後の手段にする。先に、用意した質問と答えから選べるようにする。

**ただし、最初の公開は順番3（AIが答える）だけで始める。** 何がよくある質問かは、公開して記録が溜まるまで分からないためである。順番1・2は、記録で多かった質問をもとに第2段階で足す（判断の記録 D-15 の見直し）。

| 順番 | 利用者がすること | 答えの出どころ | 速さ・料金 |
|---|---|---|---|
| 1 | チャット画面の端にある「〜の質問」の一覧から、自分の疑問に近いものを選ぶ | 講義の取り込み時に作って承認した答え | 一瞬。料金なし |
| 2 | 一覧にない、または読んでも分からないので、自分の言葉で質問を送る。中身が用意した質問と同じなら、その答えを返す | 同上（AIは「どの答えが合うか」を選ぶだけ） | 速い。料金は少し |
| 3 | どれにも当てはまらない | AIが講義資料をもとに書く | 数秒。料金は1問約0.4円（見積もり） |

用意した答えは、事前に人が読んで承認したものなので、作り話が混ざらない。

## 5. 成功の基準

数字はすべて仮。公開後の記録を見て見直す。

| 番号 | 基準 | 目標（仮） | 測り方 |
|---|---|---|---|
| S-1 | 質問を送ってから最初の文字が出るまで | 3秒以内 | APIの記録（所要時間） |
| S-2 | 答えが全部出るまで | 15秒以内 | 同上 |
| S-3 | 評価用の質問集で、資料に沿った正しい答えになる割合 | 80%以上 | 評価用の質問集（設計書 9章） |
| S-4 | 資料にない質問で、作り話をしない割合 | 100% | 同上 |
| S-5 | 出典（第何回か）が付いている答えの割合 | 100% | 同上 |
| S-6 | 「資料にはありません」で終わった質問の割合 | 20%以下 | 質問の記録（`result`） |
| S-7 | 月のAI利用料 | 2,000円以内（決定） | Claude API の利用状況 |
| S-8 | （第2段階から）用意した答えを開いたあと、AIに進まずに済んだ割合 | 60%以上 | 用意した答えの件数の記録（開いた数と、AIに進んだ数） |

「役に立った／立たなかった」のボタン（F-22）には目標を置かない。ほとんどの人は押さないので、押された割合は成功の基準にならない。代わりに、「立たなかった」が押された質問は全件読み、資料や指示文を直す材料にする。

## 7. やらないこと（最初の公開では）

| やらないこと | 理由 |
|---|---|
| 画像・スクリーンショットの受け付け | 料金と作りが大きくなる。まず文字だけで効果を確かめる |
| 利用者のPCを操作する・コードを代わりに書く | 目的は「講義内容が分かること」。作業の代行は Claude Code の役割 |
| 講義資料にない一般的なAI相談 | 作り話のおそれが増え、料金も読めなくなる |
| ログイン・利用者ごとの履歴 | アプリ自体にログインがない。組み込み先の仕組みが決まってから合わせる |
| 会話のサーバー保存 | 「個人の履歴をクラウドへ送らない」というアプリの方針に合わせる |
| 管理画面 | 最初はデータベースへの問い合わせで足りる。質問が増えてから作る |
| ベクトル検索 | 資料は文章として約6.9万字（実測）で、目次から選ぶ方式で足りる（判断の記録 D-04） |

## 8. 機能以外の要件

### 8.1 速さ

- 最初の文字まで3秒以内、全部出るまで15秒以内（仮。S-1・S-2）。
- 待っている間は「資料を探しています」などの状態を画面に出し、止まって見えないようにする。

### 8.2 料金

- 利用者のチャットは Claude API を使うため、質問のたびに料金がかかる（サブスクでは動かせない）。
- 月の上限額は2,000円。Claude API 側の月の上限額をこの金額に設定する（設定はドル建てなので、そのときの為替で換算する）。
- 1日の上限は、見積もりの1問約0.4円から逆算して150問とする（150問 × 0.4円 × 30日 ＝ 約1,800円）。1問あたりの料金は実測ではないので、公開後に測って数を見直す。
- 1問あたりにAIへ渡す資料の量に上限を設ける（仮：かたまり4個まで）。
- モデルは安いもの（Haiku 5.5）から始め、品質が足りないときだけ答えを書く側を上げる。

### 8.3 個人情報と秘密情報

- 名前・メール・IPアドレス・ブラウザのIDを質問の記録に保存しない。
- 会話の続きはブラウザ内だけに保存する。サーバーには1問ずつばらばらに記録する。
- チャット画面に「質問内容は改善のために匿名で記録されます。APIキーやパスワードは貼らないでください」と表示する。
- 利用者がAPIキーを貼ってしまった場合に備え、AIに送る前と記録する前に伏せ字にする（F-24）。

### 8.4 安全

- APIキーはサーバー側の秘密情報として保存し、ソースコードやブラウザに出さない。
- 質問文は「信頼できない入力」として扱う。質問文の中の命令（例：「これまでの指示を無視して」）には従わない。
- 答えは文字として表示し、HTMLとして解釈しない。

### 8.5 止まったとき

- AIや資料の読み込みに失敗したら、「いまは答えられません。時間をおいて試してください」と表示する。クエスト本体（問題・講義ノート）はチャットが止まっても動き続ける。

### 8.6 運用

- チャット側の更新は、クエストアプリの公開手順に影響しない。
- 組み込み先のサイトからも同じAPIを呼べる（呼び出しを許可するサイトを設定で足せる）。

## 9. 制約と前提

| 項目 | 内容 |
|---|---|
| クエストアプリ | Next.js の静的出力。Cloudflare Pages で公開。サーバー側の処理は集計用の Worker だけ |

## 11. 用語

| 用語 | この文書での意味 |
|---|---|
| かたまり | 資料を話題ごとに分けた単位。AIにはこの単位で渡す |
| 目次 | かたまりの見出しを並べた一覧。AIはまずこれだけを見て、読む資料を選ぶ |
| 出典 | 答えのもとにした資料の場所（期・回・ページ） |
| ストリーミング | 答えを全部作ってから返すのではなく、できた順に少しずつ返すこと |
| D1 | Cloudflare のデータベース。中身は SQLite で、SQL で操作する |
